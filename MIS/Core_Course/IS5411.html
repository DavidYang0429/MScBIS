课程目标

This course focuses on systems analysis and design with an emphasis on the development of information systems. Methods of system documentation are examined through the use of object-oriented and structured analysis tools and techniques for describing processes, use cases, data structures, system objects, file designs, input and output designs, and program specifications.

课程评论（选自2022版选课心得）

  1. 主要是讲流程图，系统设计。平常要求严，对作业要求高，但是只要平常好好学，作业好好 做，期末没什么大问题。
  2. 作业: Project 选一个实际存在的组织，发现组织的业务问题，用 UML 图设计一个系统来解 决这些问题。
  3. 考试:概念题大概 30%，PPT 上都有，案例题 70%，是教材的课后习题，可能老师会稍作 改动。
  4. 课程难度:应该是第一学期最难的课，同时也是信息系统方面的核心课程，学好 SAD 对理 解其他课程有很大帮助。
  5. 老师不点名，但上这门课有点难度，去不去全凭自觉，但不去肯定就不懂啦哈哈。平时作业都 是小组完成，无个人作业。小组还需要完成一个 project，且需要 final pre。最终考试需要 背概念，是闭卷。认真复习，给分不差。

很有用，对于想往系统分析的同学是一个不错的选择，在公司里会是一个backup的部门。

课程评论（2023版）

大陆老师Liu Ben的课程，这门课理论部分会讲如何分析系统，设计系统，实践部分是画UML图表，时序图活动图类图之类的，接触过数据库设计写过程序的同学学起来会容易一些。Liu Ben老师上课很有逻辑环环相扣，上课认真听基本就够了。小组项目和期末考试内容差不多，做项目的时候就相当于练习了。小声说一句老师每年的考试题都差不多，所以最后虽然期末考试闭卷但大家考试分数都不低，基本上小组项目质量决定了成绩。小组项目最后展示前可以跟老师约个office hour让老师挑挑毛病，修改后再提交，容易得高分。

——Lay MIS

课程内容：该课程是由一位内地老师（刘騫(Dr. LIU Ben)）进行教授的，课程内容主要围绕系统分析，系统设计展开，具体来说要画各种图。

课程难度：难度偏难，尤其对于文科同学来说刚开始会不知所云，其实个人觉得如果先上5413（数据库系统）的课再上这一门课会好非常多，因为5411涉及到较多的数据库知识，所以同学们在修这门课的同时也可以多了解下数据库知识，如3NF等。

考核方式：上课考勤+回答问题+小组作业+小组项目+线下闭卷考试。

就业帮助：让同学可以看懂互联网产品的设计过程（因为一般互联网公司的内部文件会有研发部的文档，他们在设计业务系统的时候就会做这种系统设计的UML图，所以这也能够让你理解产品的设计过程以及原理）。

——熊 MIS

MIS的必修课之一，liu ben老师讲的很有逻辑也很详细，期末有小组的project，疯狂画图。这里和后面的database5413课程会有互通的地方，好好学还是很有用处的。

——Peggy MIS

如果没有这方面相关知识的同学一开始上会比较吃力。每节课课后自己消化并且可以找youbute看看，后期的内容基本都可以融会贯通。闭卷考试，所以考前一定一定要看past test，背也要背下来（血泪教训）

——胡老ber MIS

教授有点龟毛但是上了课跟着做基本不会太差，有点主观的一门课

——Regulus MIS

这是一门和UML Model有关的课程，学起来绝对不轻松，我个人认为它的难度甚至高于零基础学Python的难度。
MIS要修的话要做好心理准备（MIS必修）。FIT除非说有学过或者很喜欢，不然不建议来没苦硬吃哈哈哈哈（

课堂：

  1. 这门课只开在semA，挂了搞不好就要延毕一年，所以选了千万别挂。
  2. 如果要选这门，很推荐同时选5413，特别是对MIS分支，因为这两门都是MIS必修。5413教的EER图和3NF范式能极大帮助你厘清这门课一些Models的逻辑。
  3. 核心内容是Class Diagram，Activity Diagram，First-cut Class Diagram和Design System Sequence Diagram，这四个models考试要考且是手绘。其他models只需在小组作业中呈现。
  4. 老师上课很喜欢点人提问，不能说自己不会，老师会一直压力你直到你回答，但是实际上他对回答很宽容，就算答错也没关系，所以尽量说点什么就好，算是看个态度。

作业：

  1. 所有平时作业都要以小组为单位完成，基本上每周都有一个作业，事情很多，小组八个人为一组。
  2. 首先说明，这门课组队很重要，组长人选更是极其重要，组长如果没学懂，或者很摆、决断力执行力不够，这组基本离翻车不远了。
  3. 小组项目简单概括下就是给一个现实中存在的公司（必须是你能联系的到的，小公司也不要紧）做系统设计，并给这个系统设计6-12个功能，然后用各种UML图来呈现这些功能是怎样运作的。整个学期都是在为这件事不断添砖加瓦。
  4. 不建议设计太多功能，因为每一个功能都要用6个UML Model来呈现。我们当时就是最开始设计了12个功能，没有意识到工程量的问题，后面也没法再换了。最后算上一些统合性的UML图，整个学期下来画了将近80个UML图，任务量很大，非常的累。
  5. 再说回组长，组长必须要好好学。谁都可以不懂，但组长不能不懂，因为大家把UML图画好后，每一张图有没有错误还得靠组长把关和修改。并且，学着学着忽然发现之前做的设计和新学的知识产生冲突，又要回头去重新改设计、改图的情况也屡见不鲜。如果组长是半桶水，想着混一混就过去了，导致最后呈现出来的小组作业和老师教的相差十万八千里，会被老师批的非常惨。
  6. 交作业都是用drop box而非canvas，由组长创建一个共享文件夹并由组长管理，然后组员和老师加入。作业都以组为单位上传，一组只需上传一份。
  7. 基于以上，这门课当组长会非常！非常累！我在所有组员都靠谱的情况下，依然搞的十分辛苦。有其他组的组长还遇到那种不仅不学还捣乱的组员，更是地狱级副本。当组长做好心理准备。
  8. 最后需要填全组成员的贡献率表，如果有团队蛀虫这时候就可以一致给他低贡献了。相对应的，组长或者比较辛苦的人也可以协商高点贡献。
    我最后就商量让组员们都挪了点贡献给我这个组长，感谢老板们哈哈哈哈。

展示：

  1. 最后两周会被用来项目展示，需要全组都上台，但不必所有人都讲，可以一两个人讲然后其他组员当背景板。
  2. 有提问环节，除了老师会问，台下的同学也需要提问，提问的话可以加分。对自己的项目一知半解，随便就被问倒了肯定是不行的，所以又回到那句话，天塌了组长也得顶得住。
  3. 时间管理很重要，老师看似不明显强调，实际上很看中这个。当时我就控制在10分钟多点就pre完了，立马得到了老师的称赞。

对LIU Ben的印象：

  1. 我倾向于用“狡猾”来形容LIU Ben，你很难从他这里占到什么便宜或者讨到什么好处，一切都被他算计的清清楚楚。
    譬如他会用点人回答问题的方式逼你课前复习；
    譬如他会反复提他可以随便挂人，挂了你想重修就得明年再学，来吓你认真准备考试；
    譬如他会说他曾把某组展示时联网下载PPT的时间算进了他们的展示时间里，以此建议大家最好展示时带U盘。
    从最终目的来看，你没法说他有问题，但就过程而言，你确实被他以一种不太舒服(？)的方式拿捏了，很微妙。
  2. 抛开第一条不谈，LIU Ben本身讲课还是讲得不错的。
  3. LIU Ben本人也很清楚他这节课里团队合作的重要性，所以他对Free Rider是零容忍的。如果大家一起举报Free Rider，他会严肃约谈那个人。最后划分贡献如果有争端，他也会公正处理。

考试：

  1. 闭卷，画2个Activity Diagrams，1个Class Diagram，1个First-cut Diagram和1个Design System Sequence Diagram，总共五个图。纯画图，近几年考试应该都是这个题型结构。
  2. B站上搜5411，有一个关于20-21年semA的真题的视频，可以参考。
  3. 其中Class Diagram是最难完全确定清楚的，建议先只画几个关键的Entities和关系后就直接跳后面的题，后面的图画完后再回来完善和补充。

如果要算semA最累的课，5411一定能上榜。如果当了这门课的组长，那更是重量级。
By the way，我最后拿的是A。

Tips：如果时本科学过类似课程的不建议选这门课，因为UML真的是每个老师一个版本，新老知识在脑子中打架的感觉很痛苦。不过没有学习过系统设计的同学可以把这门课当扫盲课程学习。

关于课堂：

  • 这门课没有签到，但去了就会面对老师的随机提问。老师一定会追问到底，所以即使不知道也说点什么，他对答案的容忍度还是很高的。建议不要坐的太显眼，穿杂色衣服会稍微降低被提问概率。当然如果本身比较显眼就听天由命，反正我被点了三次。不过为了搞懂在讲什么建议还是去听课。
  • 是一门很需要理解的课程，需要分析每个图的用途，所以建议每次课后都试着画一画ppt里的例子，边画边思考。
  • 前两个小时是上课，最后一小时是实验，实验课主要是布置每周的小组作业，如果可以的话建议课上就把任务全部完成，这样可以不用再约时间小组讨论。
  • 重点在于最后的design部分，老师最后花了三四个星期讲了同一个内容。

关于小组作业：

  • 小组作业需要联系一个真实存在的公司，解决他们的一个问题，可以找本科同学，（需要填联系方式）至于问题可以随便想，但最好是简单的，能想到该怎么实现的，因为后面的设计部分会放大系统的难点。

  • 好的组长真的非常非常重要。这门课的组长任务量不逊色于5540。同时组员也很重要，这门课需要理解，所以如果来的很少的话可能会完全不理解该怎么写。

  • 大部分的周次会有单独的小组作业，期末还需要提交一个完整的系统分析设计图。他会要求到一定周次提交某一部分的设计图，所以不要拖延，尽早开始。

  • 因为设计时需要考虑数据库的部分，所以建议和5413一起选，当然本科学过类似课程的可以跳过。

  • 由于任务量繁杂且很多都是图片，所以组长需要做好版本控制并时刻准备修改前面的设计部分。

关于考试：

  • 和前几年的试卷差不多，给出一段系统描述，要求画出活动图，类图，first-cut 类图，设计ssd。时间比较紧张，建议一边读一边思考怎么画，记得带尺子和铅笔橡皮。

关于老师：

一个有着很奇怪幽默点的老师，比如他说过不要以为我的挂人量有限制，我可以挂整个班。他也总能精准猜到学生不想干什么然后强迫我们去做。从折磨程度上liuben一定可以排在第一名。尽管从考试结果来看他没有表现得那么无情，但他确实成功留下了一个“坏人”的形象。

借一个组员的评价：宽于待己，严于律人。注意不要把他写的东西当成绝对的答案，因为他自己经常会犯一些小错误，但你不可以犯。
